# 싱큐 시연 영상 녹화 순서

> 형식: 화면 녹화 후 내레이션과 자막을 후편집으로 추가
> 권장 길이: 1분 50초~2분
> 핵심 메시지: **가장 많은 표를 받은 선택과, 조건 변화에 가장 견고한 선택은 다를 수 있다.**

## 1. 영상의 한 줄 서사

팀원 4명 중 3명이 A를 선택했지만, 싱큐로 판단을 스트레스 테스트하자 B가 더 견고했고 구현 가능성의 중요도가 1%p만 높아져도 결과가 B로 뒤집혔다.

실제 데모 데이터의 확정 수치는 다음과 같다.

- 1순위 득표: A 75%, B 25%, C 0%
- 현재 점수 1위: A `3.906` — B `3.900`과 거의 동점
- Decision Stability: A 47.4%, B 52.6%
- Most Robust Choice: B
- Flip Point: 구현 가능성 중요도 +1%p
- Hidden Conflict: A를 다수가 골랐지만 구현 가능성 평가는 크게 갈림

기존 발표 문서에 있는 `B 득표 75%`, `B Stability 82.2%`, `발표 임팩트 +8%p`는 현재 `demo_data.json` 결과와 다르므로 영상에서는 사용하지 않는다.

## 2. 녹화 전 준비

1. 브라우저 알림과 북마크 바를 숨긴다.
2. 화면 배율은 100%, 창 크기는 1440×900 이상으로 맞춘다.
3. LIVE API 모드인지 확인한다. 화면에 `MOCK MODE`가 보이면 녹화하지 않는다.
4. 데모용 방을 두 개 준비한다.
   - 방 A: 방 생성과 한 명의 입력 과정을 보여줄 새 방
   - 방 B: `demo_data.json`의 4명 입력이 완료된 결과용 방
5. 결과용 방 코드는 메모해 두되 영상에는 터미널이나 준비 과정이 나오지 않게 한다.
6. 마우스 이동은 천천히 하고, 클릭 후 화면이 안정된 상태를 1초 이상 유지한다.
7. 실제 입력과 스크롤만 녹화한다. 목소리와 자막은 화면 편집 후 추가한다.

결과용 방은 녹화 전에 다음 명령으로 로컬 LIVE API에 준비할 수 있다.

```bash
.venv/bin/python scripts/load_demo.py --base-url http://127.0.0.1:8000
```

## 3. 권장 녹화 순서

### 클립 1 — 브랜드와 문제 제시

- 권장 시간: 0:00~0:08
- 화면: 싱큐 첫 화면 또는 방 만들기 화면 상단
- 동작:
  1. `싱큐` 로고와 `합의보다, 더 나은 선택.`이 보이게 2초 정지한다.
  2. 상단의 `방 만들기`를 클릭한다.
- 자막 핵심: `팀의 만장일치, 정말 같은 판단일까요?`
- 내레이션 핵심: “싱큐는 결정을 대신하지 않고, 팀 결정이 얼마나 견고한지 검증합니다.”

### 클립 2 — 방 생성

- 권장 시간: 0:08~0:25
- 화면: 방 만들기
- 동작:
  1. 질문에 `6시간 해커톤에서 어떤 아이디어를 만들까요?`를 입력한다.
  2. 선택지 A·B·C를 붙여넣는다.
  3. 평가 기준 `창의성`, `구현 가능성`, `발표 임팩트`를 붙여넣는다.
  4. 참여 인원은 4명으로 둔다.
  5. `익명 제출`이 선택된 모습을 보여준다.
  6. `방 만들기`를 클릭한다.
- 자막 핵심: `질문 · 선택지 · 평가 기준 · 익명 여부 설정`
- 편집: 텍스트 입력 구간은 1.5~2배속 처리한다.

### 클립 3 — 한 명의 익명 판단 입력

- 권장 시간: 0:25~0:45
- 화면: 의견 입력
- 동작:
  1. 옵션별 점수를 몇 개 선택하는 모습을 보여준다.
  2. `구현 가능성` 가중치를 높이는 모습을 보여준다.
  3. 1순위 옵션을 고른다.
  4. 이유에 `임팩트는 크지만 오늘 안에 구현할 수 있을지 걱정됩니다.`를 입력한다.
  5. 익명 안내 문구가 보이게 잠시 정지한다.
  6. 제출한다.
- 자막 핵심: `표 하나가 아니라 점수 · 중요도 · 이유를 함께 수집`
- 편집: 9개 점수를 모두 누르는 장면을 실시간으로 보여주지 말고 중간을 점프 컷한다.

### 클립 4 — 익명 대기 화면과 팀 입력 완료

- 권장 시간: 0:45~0:56
- 화면: 제출 현황
- 동작:
  1. `1 / 4명`과 “개별 답변은 공개하지 않습니다” 문구를 2초 보여준다.
  2. 점프 컷으로 미리 준비한 결과용 방의 `4 / 4명` 화면으로 전환한다.
  3. `결정 안정성 분석하기`를 클릭한다.
- 자막 핵심: `누가 무엇을 냈는지는 숨기고, 완료 여부만 공유`
- 주의: 2·3·4번째 제출 과정을 반복 녹화하지 않는다.

### 클립 5 — 표와 안정성의 반전

- 권장 시간: 0:56~1:16
- 화면: 분석 결과 상단 → 득표 → Stability
- 동작:
  1. 결과 화면의 `합의보다, 더 나은 선택.`에서 1초 정지한다.
  2. `표는 이렇게 갈렸습니다`에서 A 75%를 보여준다.
  3. 아래로 천천히 내려 Stability A 47.4%, B 52.6%를 보여준다.
- 자막 핵심:
  - `3명 중 3명이 아니라, 4명 중 3명이 A 선택 — 75%`
  - `하지만 조건을 흔들면 B가 52.6%로 더 안정적`
- 내레이션 핵심: “가장 많은 표를 받은 A와, 가장 자주 살아남은 B가 달랐습니다.”

### 클립 6 — 숨은 갈등, Flip Point, Robust Choice

- 권장 시간: 1:16~1:35
- 화면: Hidden Conflict → Flip Point → Most Robust Choice
- 동작:
  1. A의 구현 가능성 평가가 갈린다는 Hidden Conflict를 보여준다.
  2. 구현 가능성 중요도가 1%p만 높아져도 B로 바뀐다는 Flip Point를 보여준다.
  3. 어두운 배경의 `Robust choice — B. 팀 의사결정 도구`에서 2초 정지한다.
- 자막 핵심: `결정을 뒤집는 최소 변화: 구현 가능성 +1%p`
- 내레이션 핵심: “싱큐는 B가 정답이라고 말하지 않습니다. 지금 결정이 얼마나 얇은 차이 위에 있는지 보여줍니다.”

### 클립 7 — 라이브 시뮬레이터와 논의 안건

- 권장 시간: 1:35~1:55
- 화면: Live simulator → Discussion agenda → Devil’s Advocate
- 동작:
  1. `구현 가능성` 슬라이더를 조금 올린다.
  2. 실시간 순위가 B로 바뀌고 `순위가 뒤집혔어요`가 나타나는 순간 2초 정지한다.
  3. 논의 안건까지 스크롤한다.
  4. Devil’s Advocate 질문 두 개를 천천히 보여준다.
- 자막 핵심:
  - `슬라이더를 움직이면 브라우저에서 즉시 재계산`
  - `AI는 숫자를 만들지 않고, 결정이 깨지는 조건만 질문`
- 내레이션 핵심: “팀은 이제 모든 의견을 다시 논의할 필요 없이, 구현 가능성이라는 핵심 쟁점에 집중할 수 있습니다.”

### 클립 8 — 엔딩

- 권장 시간: 1:55~2:00
- 화면: 결과 화면 하단의 브랜드 문구
- 동작: `싱큐 · 합의보다, 더 나은 선택.`에서 3초 정지 후 페이드아웃한다.
- 마지막 자막: `결정은 팀이. 견고함의 검증은 싱큐가.`

## 4. 편집 순서

1. 클립 1~8을 먼저 연결해 무음 러프컷을 만든다.
2. 로딩, 긴 입력, 반복 제출 구간을 삭제한다.
3. 화면 전환 지점에만 짧은 디졸브 또는 4~6프레임 페이드를 사용한다.
4. 러프컷 길이를 약 1분 50초로 맞춘다.
5. 화면을 보고 내레이션을 녹음한다.
6. 내레이션 문장을 그대로 복제하지 말고, 자막은 수치와 결론만 짧게 쓴다.
7. 클릭 순간과 수치 등장 순간에 자막 타이밍을 맞춘다.
8. 배경음악은 목소리보다 충분히 작게 두거나 생략한다.
9. 마지막으로 실제 화면 수치와 자막의 수치를 대조한다.

## 5. 반드시 강조할 세 장면

1. **A 득표 75%** — 표면적 합의
2. **B Stability 52.6%** — 더 견고한 선택의 반전
3. **구현 가능성 +1%p** — 결정이 깨지는 구체적인 조건

이 세 장면이 명확하면 영상의 핵심 메시지는 전달된다. Google 로그인, AWS 배포 화면, 관리자 콘솔은 핵심 시연에서 제외한다. 로그인 기능을 보여줘야 한다면 본편 앞이나 뒤에 3초짜리 별도 보조 장면으로 추가한다.

## 6. 피해야 할 구성

- 4명의 전체 입력 과정을 모두 실시간으로 보여주기
- 터미널, API 키, AWS 또는 Google Cloud 설정 화면 노출
- 결과 화면을 빠르게 끝까지 스크롤하기
- “B가 정답이다”라고 표현하기
- 현재 데이터와 맞지 않는 82.2%, +8%p 수치 사용
- 로그인 오류나 네트워크 로딩이 포함된 상태에서 한 번에 녹화하기
